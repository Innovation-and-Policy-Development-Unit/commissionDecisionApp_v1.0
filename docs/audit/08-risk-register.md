# Risk Register

Likelihood/Impact: Low/Medium/High. Residual rating assumes only currently-existing controls, not proposed fixes.

| ID | Risk | Likelihood | Impact | Current controls | Residual | Treatment | Owner |
|---|---|---|---|---|---|---|---|
| R-01 | Confidential personnel/disciplinary documents accessed without authorization via the unauthenticated media path | **High** (no barrier at all, only requires knowing/guessing a URL) | **High** (statutory confidentiality breach) | None at the file-serving layer; RBAC exists only at the API layer, which this path bypasses entirely | **High** | Mitigate — P0-01, Phase 0 | Backend lead |
| R-02 | Full database compromise via the backup-restore endpoint | Medium (requires a `manage_roles` account, but see R-04) | **High** (arbitrary DB write, including audit-log rewrite) | Role gate only; no content/schema validation | **High** | Mitigate — P0-02, Phase 0 | Backend lead |
| R-03 | Production runs with the hardcoded fallback `SECRET_KEY` due to a deployment misconfiguration | Low (requires an env-var omission) but plausible during infrastructure changes | **High** (forges session/CSRF/reset tokens) | `.env.example` documents the correct value; no runtime enforcement | Medium | Mitigate — P0-03, Phase 0; verify current prod config as a parallel action | Backend lead / DevOps |
| R-04 | Session takeover via XSS (localStorage-stored JWTs), cascading into R-01/R-02 if the compromised account holds elevated roles | Medium (depends on an XSS vector existing somewhere in the SPA, not confirmed independently discovered in this review but the storage choice makes the consequence severe if one exists) | **High** | Partial CSP (weakened by `unsafe-inline` on the SPA shell) | **High** (as a chain risk) | Mitigate — P1-01/02, Phase 1 | Frontend + backend leads |
| R-05 | Locked-in database performance degradation / outage under email-provider latency, via the signal-hidden synchronous send inside an open transaction | Medium (depends on provider latency spikes, which are not rare for third-party email APIs) | **High** (system-wide, not just one slow request — lock contention) | None currently | **High** | Mitigate — P0-04, Phase 0 | Backend lead |
| R-06 | Recurrence of the synchronous-request-path defect pattern in future feature work (already happened twice within one week) | **High** (demonstrated pattern, no guardrail exists) | Medium (degrades UX, doesn't corrupt data on its own — except where it overlaps with R-05) | A partial fix exists for 4 of 13+ known instances; no automated regression test | Medium-High | Mitigate — P1-15 fix + guardrail test, Phase 1 | Backend lead |
| R-07 | Sovereign personnel/disciplinary data transmitted to a foreign AI provider without consent or redaction | **High** (happens automatically on ordinary use today) | Medium-High (governance/policy exposure; severity depends on legal/political sensitivity of the specific data category, which is a leadership judgment, not a technical one) | None (no opt-in, no redaction) | **High** | Requires leadership policy decision, then mitigate — P1-07, Phase 1 | IPDU Manager + PSC leadership |
| R-08 | Commission decision later challenged on procedural grounds (no quorum record, no recusal record) | Low-Medium (depends on whether a challenge ever arises, but the system provides no defense if one does) | **High** (legal defensibility of a statutory decision) | None — structurally absent | Medium-High | Mitigate — P1-14, pending PSC procedural confirmation | PSC Secretary + backend lead |
| R-09 | Audit trail found to have been altered, undermining evidentiary value in a dispute | Low (requires DB/app-server access) | **High** (undermines every other control's evidentiary claim) | Convention-only "append-only" behavior, no enforcement | Medium | Mitigate — P1-08, Phase 1 | Backend lead |
| R-10 | Data loss on multi-page forms during interrupted sessions (plausible given intermittent connectivity to outer islands) | Medium-High (context-specific, not a generic edge case) | Medium (rework/frustration, not data-integrity-breaking, but erodes trust in the system) | None | Medium | Mitigate — P1-11, Phase 1 | Frontend lead |
| R-11 | Named individual / commercial pricing exposure via the tracked git repository | Medium (depends on repo visibility/sharing) | Medium (reputational/commercial, not personal-safety-critical based on content reviewed) | None currently; flagged, not yet remediated per explicit instruction | Medium | Records/legal decision — P0-05 | IPDU Manager + legal |
| R-12 | Retention policy non-enforcement leads to unbounded data growth and non-compliance with any future records-retention audit | **High** (confirmed currently not scheduled at all) | Medium (operational/compliance, not an acute breach) | A command exists but never runs | Medium-High | Mitigate — P1-13, Phase 1 | Backend lead + records/legal |
| R-13 | A regression ships silently because no CI gate exists | **High** (demonstrated — no pipeline at all today) | Medium (varies by what regresses; could be High if it's a security regression like R-06) | None | Medium-High | Mitigate — CI pipeline, Phase 1 | DevOps/backend lead |
