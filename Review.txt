Critical — will produce wrong numbers or errors in production
1. Annual Report decision counts are inflated and don't reconcile with their own ministry table (reports/annual_report.py). Two causes, same root: _first_decisions counts every WorkflowEvent reaching approved/rejected/returned, but (a) when a decision is recorded, the cascade block in views.py creates mirror events for attached child submissions — so a Form 2-1 with three attached job descriptions counts as four decisions; and (b) events belonging to trashed submissions still count in total_decided while the ministry table (built from Submission.objects) excludes them — so the headline and the table disagree. Intake correctly excludes attachments; decisions don't. For a Parliament-facing document this is the most important finding. Fix: filter decided keys through Submission.objects.filter(is_attachment=False) before counting outcomes.

2. analytics_overview_view is still broken (views.py:8906) — the bug I flagged in the first session (task chip task_444303b4, never actioned) references nonexistent WorkflowStage.DECIDED_APPROVED/DECIDED_REJECTED/WITHDRAWN and a nonexistent submitted_at field. The /analytics route still mounts AnalyticsDashboard.jsx, which calls it → 500 for anyone who navigates there. Either fix it or remove the route; it's been dead weight twice over.

High — behavior gaps that contradict the features' own definitions
3. The overdue nag and the implementation dashboard disagree about "overdue" (tasks.py notify_overdue_implementation_reports). The dashboard treats a decision with no explicit due date as overdue after the default IMPLEMENTATION_TARGET_DAYS; the daily reminder task filters implementation_due_date__lt=today only — so the majority of decisions (those without explicit dates) show as overdue on the Secretary's dashboard but never trigger a reminder. The accountability loop is open exactly where it matters. Fix: apply the same default-target logic in the task.

4. Decision service has no transaction around supersede→create→render (decision_service.py). If WeasyPrint fails mid-serve, earlier unacknowledged services are already marked superseded and a PDF-less service row exists, with no notifications sent. Recoverable by re-serving, but wrap supersede+create+render in transaction.atomic() so a failed serve leaves no trace.

Medium
5. ministry_recipients notifies ministry HR + DG, but MINISTRY_ACK_ROLES also lets dept_admin acknowledge — someone can acknowledge a service they were never notified of. Align the two sets one way or the other.
6. SubmissionLog bulk delete swallows per-item 403s silently — a ministry user "deleting" 10 items where 7 are non-drafts sees no feedback that 7 survived. Count failures and toast the result.
7. Frontend date filters built with toISOString() (ImplementationDashboard periods) compute UTC dates — off by one day around midnight in Pacific/Efate (UTC+11). Use local-date formatting.
8. Seeded demo data (migration 0052: ministries, users, submissions, Meeting No. 12) exists in every production database and now flows into the implementation dashboard, workload, and annual report. Before go-live you need a cleanup command — the demo submissions are deletable via the new trash, but the seeded users/meeting need a management command.

Low / hardening
9. WorkflowEvent has no index on (new_stage, created_at) — every rollup scans it. Trivial volumes today; add the index in the next migration batch.
10. Annual-report and implementation PDF generation are synchronous in the request — fine at PSC scale, but if they ever slow down, the Celery tasks already exist to move them behind a poll.
11. SubmissionViewSet destroy RBAC was tightened (correctly), but the same loose-permission pattern (HasProfilePermission = "has any profile") still guards several mutating endpoints elsewhere; the RBAC permission registry exists but isn't consistently enforced. Worth a dedicated pass someday — it's the largest remaining security surface.
12. Docs: SCDMS_API_DOCUMENTATION.md covers the implementation endpoints but not decision-service, workload summary, annual report, or trash — worth adding before the IPDU handover.
